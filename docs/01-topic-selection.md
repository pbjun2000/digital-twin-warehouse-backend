# 프로젝트 주제 선정 과정

## 1. 주제 선정 배경

빅프로젝트 주제를 선정하면서 단순한 AI 모델 구현보다 실제 서비스 형태로 구성할 수 있고, 백엔드·AI·데이터·인프라 기술을 함께 활용할 수 있는 주제를 찾고자 했습니다.

특히 다음 기준을 중요하게 고려했습니다.

- 실제 산업 현장의 문제를 다루는가
- AI가 서비스의 핵심 기능으로 사용되는가
- Spring Boot 기반 백엔드 경험을 충분히 보여줄 수 있는가
- 프로젝트 기간 안에 구현 및 시연이 가능한가
- 적용 전후의 성능을 수치로 비교할 수 있는가
- 실제 데이터가 부족해도 시뮬레이션으로 검증할 수 있는가

---

## 2. 검토한 방향

초기에는 제조 원인 분석, 이커머스 검수, 자율 창고 운영과 같은 B2B 서비스 주제를 검토했습니다.

| 검토 방향 | 장점 | 한계 |
|---|---|---|
| 제조 원인 분석 | 산업 적용성과 지식그래프 활용성이 높음 | 공정별 원인·조치 데이터 확보가 어려움 |
| 이커머스 검수 | 서비스 구조가 명확하고 구현 가능성이 높음 | 기존 룰 기반 서비스와의 차별화가 필요함 |
| 자율 창고 운영 최적화 | 백엔드, 실시간 처리, 그래프, AI 최적화를 함께 활용 가능 | 다중 로봇 충돌 방지와 시각화 난도가 높음 |

---

## 3. 최종 선정 주제

### LARO: Digital Twin 기반 자율 창고 운영 및 다중 로봇 작업 최적화 시스템

창고 구조와 로봇 상태를 Digital Twin으로 관리하고, 여러 로봇의 작업 할당과 이동 경로를 최적화하는 시스템입니다.

창고 내 이동 가능한 위치를 Node로 표현하고, 노드 사이의 연결 관계를 Edge로 구성합니다.

여러 로봇이 동시에 작업할 때 발생할 수 있는 충돌, 대기와 정체를 줄이고, 관리자에게 창고 운영 상태를 통합적으로 제공하는 것을 목표로 합니다.

---

## 4. 문제 정의

물류창고에서 여러 로봇이 각각 독립적으로 최단 경로를 계산하면 다음과 같은 문제가 발생할 수 있습니다.

- 동일한 통로나 교차 지점에서 충돌과 대기 발생
- 특정 구간에 로봇이 집중되어 정체 발생
- 장애물이나 통로 차단 시 기존 경로 사용 불가
- 배터리가 부족한 로봇에 작업이 할당될 가능성
- 창고 구조, 로봇 상태와 작업 정보가 분산되어 운영 상황 파악이 어려움
- 최적화 적용 전후의 효과를 정량적으로 비교하기 어려움

---

## 5. 선정 이유

### 시뮬레이션을 통한 검증 가능

실제 기업의 로봇 이동 이력과 작업 데이터를 확보하지 못하더라도, 창고 지도와 작업 시나리오를 구성하여 데이터를 생성할 수 있습니다.

동일한 조건에서 기존 방식과 최적화 방식을 반복 실행하고 결과를 비교할 수 있다는 점을 중요하게 평가했습니다.

### AI 기능의 역할이 명확함

본 프로젝트에서 AI는 단순한 설명 기능이 아니라 다음 역할을 수행합니다.

- 로봇 상태와 작업 우선순위를 고려한 작업 할당
- 다중 로봇 이동 경로 최적화
- 충돌, 지연 및 정체 상황 탐지
- 관리자 자연어 명령을 작업 계획으로 변환
- 최적화 결과와 운영 현황 설명

### 백엔드 기술 활용 범위가 넓음

프로젝트를 통해 다음과 같은 백엔드 경험을 확보할 수 있다고 판단했습니다.

- Spring Boot 기반 REST API 설계
- PostgreSQL 업무 데이터 관리
- Redis 실시간 상태 관리
- Neo4j 창고 이동 그래프 관리
- WebSocket 실시간 데이터 전달
- FastAPI 최적화 서버 연동
- Docker 기반 개발 환경 구성

### 정량적 성능 비교 가능

기존 방식과 최적화 방식에 동일한 시나리오를 적용하여 다음 지표를 비교할 수 있습니다.

- 전체 작업 완료 시간
- 로봇 평균 대기 시간
- 총 이동 거리
- 충돌 및 교착 발생 횟수
- 단위 시간당 처리 작업 수

---

## 6. 기술 구성 방향

| 영역 | 기술 | 역할 |
|---|---|---|
| Frontend | React | 창고 지도와 로봇 상태 시각화 |
| Backend | Spring Boot | 창고, 로봇, 작업과 경로 API 제공 |
| AI Server | FastAPI | 경로 최적화와 시뮬레이션 수행 |
| Database | PostgreSQL | 창고, 로봇, 작업과 실행 이력 저장 |
| Cache | Redis | 로봇 위치, 배터리와 실시간 상태 관리 |
| Graph DB | Neo4j | Node와 Edge 기반 창고 연결 구조 관리 |
| Optimization | cuOpt, MAPF | 작업 할당 및 충돌 없는 경로 탐색 |
| Infrastructure | Docker | 개발 및 실행 환경 구성 |

---

## 7. 개인 담당 영역

백엔드에서 창고 구조, 이동 그래프와 경로 최적화 서버 연동 영역을 담당합니다.

- Warehouse, WarehouseNode, WarehouseEdge, WarehouseZone API 구현
- Node와 Edge 기반 창고 이동 그래프 설계
- ChargingStation 및 창고 레이아웃 통합 조회 구현
- Neo4j 그래프 데이터 동기화
- FastAPI 경로 최적화 서버 연동
- 경로 계산 및 재계산 결과 저장

---

## 8. 최종 결정

자율 창고 운영 최적화 주제는 다음 이유로 프로젝트에 가장 적합하다고 판단했습니다.

- 시뮬레이션을 통해 데이터 생성 가능
- AI 기능의 역할이 명확함
- Spring Boot 백엔드 경험을 충분히 활용 가능
- PostgreSQL, Redis, Neo4j의 역할을 구분해 설계 가능
- FastAPI와 최적화 서버 연동 경험 확보 가능
- 최적화 적용 전후 결과를 수치로 비교 가능

따라서 최종 주제로 **LARO: Digital Twin 기반 자율 창고 운영 및 다중 로봇 작업 최적화 시스템**을 선정했습니다.
